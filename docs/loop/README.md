# Loop Engineering 文档空间

本目录是项目迭代闭环（loop）的**运行状态记录空间**，区别于另外两类文档：

| 文档空间 | 职责 | 时间属性 |
|:---|:---|:---|
| `docs/loop/`（本目录） | 跨版本的闭环状态：当前目标、开放问题、验证流水、设计方案 | **现在进行时**，持续更新 |
| `docs/iterations/` | 单版本实验的详细数据与结论（v9/v10/.../v18 各一篇） | 历史快照，归档不回填 |
| `docs/knowledge/` | 沉淀的量化研究准则、规范、方法论（长期有效） | 长期知识，按需修订 |

## Loop Engineering 理念

每一轮迭代是一个**闭环**：目标 → 问题 → 假设/方案 → 执行 → 验证 → 沉淀。闭环的价值在于：

1. **目标显式化**——每轮迭代开始前，把"这轮要解决什么、验收标准是什么"写进 `goals.md`，避免边做边漂移。
2. **问题留痕**——识别但本轮不解决的问题写入 `problems.md`，防止遗忘，也防止误把多个问题塞进一轮。
3. **方案可追溯**——每个设计方案单独成文放 `design/`，记录"改什么、为什么有效、预期效果、验证标准"，事后可复盘方案质量。
4. **验证流水化**——`verification_log.md` 按时间倒序记录每轮验证的输入/输出/判定，单次回测结论不可信（随机种子敏感），流水让趋势可见。
5. **沉 plate 到知识库**——验证后确认的规律，从本目录提炼到 `docs/knowledge/`，从"运行记录"升级为"长期知识"。

## 目录结构

```
docs/loop/
├── README.md            # 本文件：理念与使用说明
├── process.md           # 6 步闭环工作流程（迭代 SOP）
├── goals.md             # 当前迭代目标 + 验收标准（每轮迭代开始时更新）
├── problems.md          # 开放问题清单（识别但未解决）
├── verification_log.md  # 验证记录流水（按时间倒序）
└── design/              # 设计方案（每个方案一文件）
    └── README.md        # 设计文档格式说明
```

## 使用方式

- **开始一轮迭代**：先读 `process.md`，按 6 步执行；在 `goals.md` 写清本轮目标与验收标准。
- **决策前**：必读 `docs/knowledge/research_principles.md`（准则）和相关代码 docstring 的失败记录，避免重复踩坑。
- **遇到非本轮问题**：记入 `problems.md`，不污染当前轮。
- **设计方案**：在 `design/` 下新建文件，命名 `{版本}_{主题}.md`（如 `v15_5b_dedup.md`）。
- **验证完成后**：在 `verification_log.md` 顶部追加一条记录；确认的规律提炼到 `docs/knowledge/research_principles.md`。
- **单版本详细数据**：写入 `docs/iterations/{版本}.md`，本目录只记跨版本状态与决策流。
