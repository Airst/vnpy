## 二、GP 因子挖掘方案

### 2.1 架构设计

新建 `core/alpha/gp_factor_miner.py`，核心特性：
- 复用 `factor_calculator.py` 中的 GPU 张量算子
- 表达式树表示法，支持序列化/反序列化
- 进化策略：锦标赛选择 + 子树交叉 + 点突变

### 2.2 算子体系

| 类别 | 算子 | 窗口限制 |
|:---|:---|:---|
| 时序一元 | ts_mean, ts_std, ts_max, ts_min, ts_delta, ts_rank, ts_decay_linear | 3, 5, 10, 20 |
| 时序二元 | ts_corr, ts_cov | 3, 5, 10, 20 |
| 截面 | cs_rank, cs_zscore | - |
| 算术 | add, sub, mul, div, abs, neg, log | - |
| 终端 | O, H, L, C, V, TR | - |

窗口参数限制在 {3, 5, 10, 20}，强制短周期特征。

### 2.3 适应度函数（第二版，改进后）

```
Fitness = |ICIR| × turnover_bonus × consistency_bonus - parsimony_penalty
```

| 组件 | 计算方式 | 作用 |
|:---|:---|:---|
| ICIR | IC均值/IC标准差，全周期1707天每10天采样 | 信号稳定性 |
| turnover_bonus | 1.0 + top10%换手率 | 奖励短周期 |
| consistency_bonus | 1.0 + (方向一致率-0.6) | 奖励跨期稳定 |
| parsimony | depth>5: 0.05/层, size>12: 0.01/节点 | 防止过拟合 |

**硬门槛：**
- |IC| >= 0.02
- 方向一致率 >= 60%（5个子区间中至少3个同向）
- 与现有因子相关性 < 0.7
- GP 因子间相关性 < 0.5

### 2.4 第一版适应度失败分析

| 问题 | 原因 | 修复 |
|:---|:---|:---|
| 7个同质化因子 | 只评估最近200天，过拟合 | 改为全周期评估 |
| Sharpe 1.00→0.78 | 同向因子叠加过度偏向单一维度 | 加方向一致性门槛 + 严格去重 |
| 表达式重复 | 去重逻辑bug | 加表达式字符串去重 |

## 三、实验结果

### 3.1 发现的 GP 因子

| 因子 | IC | ICIR | 方向一致率 | 换手率 | 表达式 |
|:---|:---|:---|:---|:---|:---|
| gp_alpha_000 | +0.050 | +0.82 | 100% | 0.81 | `div(cs_rank(TR), TR)` |
| gp_alpha_001 | -0.054 | -0.90 | 100% | 0.70 | `ts_cov(H, cs_rank(ts_std(C,3)), 10)` |

**因子解读：**
- `gp_alpha_000`: 换手率的截面排名与绝对值的比值 — 捕捉"相对流动性异常"（排名高但绝对值低 = 流动性相对改善）
- `gp_alpha_001`: 最高价与3日波动率排名的10日协方差 — 捕捉"高价股波动率变化"信号

## 四、结论与经验

### 成功因素
1. **少量高质量因子 > 大量同质因子**：2个独立因子比7个相关因子效果好得多
2. **全周期评估是必要的**：仅评估近期200天导致严重过拟合
3. **方向一致性是关键过滤器**：100%方向一致的因子在样本外表现稳定
4. **GP 因子间严格去重（corr<0.5）**：防止同维度信号过度叠加

### 注意事项
- MLP 训练本身存在随机波动，单次回测结论需谨慎
- GP 因子需定期重新挖掘以适应市场变化
- 当前 GP 只使用量价数据（OHLCV+TR），未来可扩展终端节点

### 后续方向
- 扩大 GP 搜索空间（增加种群/代数）
- 尝试更多终端节点（PE, PB, MV 等基本面数据）
- 探索不同窗口约束（允许部分 60d 窗口的中期因子）
- 多轮残差回归：后续 GP 因子在剥离已有因子信息后搜索增量 alpha
